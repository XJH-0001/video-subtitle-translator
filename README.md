# 视频实时字幕翻译

给任意网页视频加**实时翻译字幕**——类似夸克的实时字幕，但跑在 Edge（或任何 Chromium 浏览器）里，而且**音频不出你的电脑**。

- 抓取标签页声音 → 本地 Whisper 识别 → 自动翻译 → 双语字幕浮在视频上
- **字幕自动贴合视频画面**（像原生字幕）：自动找到正在播放的 `<video>`，算出真实画面区域（刨掉黑边），贴在画面底部；滚动 / 缩放 / 影院模式 / 全屏都会跟着走
- **点一下自动启动本地服务**：走 Native Messaging，不用再手动开那个黑窗口
- **字幕延迟约 0.6 秒，译文约 1.2 秒**（N 卡加速 + DeepSeek 翻译实测）；中间字幕逐字平滑显现，不跳字
- **翻译带上文**：把前两句原文一起发给模型，代词和指代翻得准（免费机器翻译接口没有这个能力）
- **字幕底色默认全透明**，像原生字幕一样完全不挡画面；靠文字八方向描边保证在亮画面上也看得清
- 支持全屏、可拖动、字号/颜色/行数随便调（想加半透明底板也行，设置页里拉一下）
- 语言**自动检测**（英/日/韩/俄/法/德/西……），翻译目标语言可选
- 识别在本地做，视频音频不上传任何服务器
- 翻译用 DeepSeek，**一部两小时电影约两三毛钱**

## 快速开始

### 第一步：装本地服务（只做一次）

需要 **Python 3.11 ~ 3.13**（[下载地址](https://www.python.org/downloads/windows/)，安装时记得勾选 *Add python.exe to PATH*）。

然后双击：

```
scripts\install.bat
```

它会自动建虚拟环境、装依赖（用清华镜像）、下载识别模型。大概 2~5 分钟，主要看网速。

> 想从命令行运行：
> ```powershell
> powershell -ExecutionPolicy Bypass -File scripts\install.ps1
> ```
> 常用参数：`-Model base`（换更小的模型）、`-SkipModel`（先不下模型）。

### 第二步：注册「自动启动」组件（安装脚本已经帮你做了）

安装脚本最后会自动注册。如果那一步失败，手动补一次：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\register-native-host.ps1
```

它做的事：编译 `native\ServerLauncher.exe` → 算出扩展 ID → 生成白名单 → 写注册表。
**为什么需要这个**：浏览器扩展不能直接启动进程（Chromium 的安全边界），
官方给的唯一通道就是 Native Messaging —— 扩展调一个注册在注册表里的本地程序，由它把服务拉起来。

> 不想注册也完全没问题。手动双击 `scripts\start-server.bat` 一样能用（那个窗口要一直开着）。

### 第三步：在 Edge 里加载扩展

1. 地址栏输入 `edge://extensions` 回车
2. 打开左下角的 **开发人员模式**
3. 点 **加载解压缩的扩展**
4. 选择本项目里的 **`extension`** 文件夹（不是项目根目录）

工具栏上会出现蓝色字幕图标。建议点一下拼图图标把它固定住。

### 第四步（强烈建议）：开启显卡加速

**如果你有 NVIDIA 显卡，这一步能把字幕延迟从 1.5 秒降到 0.5 秒以内。**

```powershell
powershell -ExecutionPolicy Bypass -File scripts\enable-gpu.ps1
```

它会装 CUDA 12 的运行库（约 1.3GB），然后真跑一次验证。实测：

| 设备 | 一次解码耗时 | 字幕延迟 |
|---|---|---|
| CPU（`small` int8，12 线程） | 1170 ms | 约 1.5 秒 |
| **显卡（`small` float16）** | **128 ms** | **约 0.5 秒** |

**为什么用 pip 装运行库，而不是装 CUDA 工具包？**

其实两条路都行，服务端两边都会自动找（pip 版目录、`CUDA_PATH\bin`、
`C:\Program Files\NVIDIA GPU Computing Toolkit\...`）。默认推荐 pip 版只是因为：

- 体积：工具包装完 6~7GB；pip 版只拉真正需要的三个运行库，约 1.3GB
- 不用管理员权限、不用改 PATH、不用重启
- **版本一定对**：CTranslate2 要 CUDA 12 + cuDNN 9，自己装工具包容易装成 11.x（DLL 名字就不是 `cublas64_12.dll` 了）
- 只装在 venv 里，卸载干净，也不影响系统里其他用 CUDA 的程序

**你已经有系统级 CUDA 工具包的话，什么都不用做** —— 服务端会自己认出来，直接就是显卡加速。
跑一下 `scripts\enable-gpu.ps1` 它会告诉你「已就绪」。

**没有 N 卡 / 显卡不可用？** 完全不影响，会自动回退 CPU（AMD、Intel 核显目前用不了 CTranslate2 加速）。
弹窗里会直接显示当前是「显卡加速」还是「CPU 识别」。

### 第五步：用起来

1. 打开任意视频网站，**点播放，确认有声音**
2. 点扩展图标 → **开启实时字幕**
3. 第一次要等几秒（自动启动服务 + 加载模型），然后字幕就出来了

快捷键 `Alt + Shift + S` 可以随时开关。

## 日常使用

| 想做什么 | 怎么做 |
| --- | --- |
| 挪字幕位置 | 弹窗点「调整位置」→ 拖动 → 按 `Esc` 完成 |
| 贴着窗口底部而不是视频 | 弹窗里把「字幕位置」改成「窗口底部」 |
| 改字号 / 颜色 / 行数 | 弹窗「快捷设置」，或右键图标 →「选项」→「字幕外观」（有实时预览） |
| 只显示译文 | 弹窗里取消勾选「显示原文」 |
| 换翻译语言 | 弹窗里的「翻译成」下拉框 |
| 换识别模型 | 设置页 →「语音识别」→「识别模型」 |
| 换翻译服务 / 填 Key | 设置页 →「翻译服务」 |
| 看服务状态 | 浏览器打开 <http://127.0.0.1:8765/> |

设置改完立刻生效，正在播的视频不用刷新。

### 字幕怎么「贴」到视频上

默认是**自动贴合视频画面**（设置里叫「自动贴合视频画面（像原生字幕）」）。它做三件事：

1. **找视频**：扫描页面上的 `<video>`，按「正在播放 + 面积大 + 在视口里可见」打分，挑最像主体的那个。
   页面上有广告、预览、背景视频时不会认错。
2. **算画面**：`<video>` 元素的框不等于画面。宽高比对不上时浏览器会加黑边（letterbox），
   所以要根据 `videoWidth/videoHeight` 和 `object-fit` 反算出**真正的画面矩形**。
   字幕贴在画面底边，而不是元素底边 —— 不然会悬在黑边里，一眼假。
3. **跟住**：`requestAnimationFrame` 持续跟踪，配合 `ResizeObserver` 和滚动/缩放事件，
   视频移动、切影院模式、进全屏、改分辨率都能跟上。

拖动保存的是**相对画面的百分比**（水平位置 + 离底部距离），所以换窗口大小、换分辨率、进出全屏之后位置依然正确。

找不到视频时（例如播放器嵌在 iframe 里，而 content script 只跑在主框架）会自动退回「贴在浏览器窗口底部」，
功能不会失灵。要改回固定模式，设置页里选「固定在浏览器窗口底部」即可。

几个值得说明的设计选择：

**为什么必须有本地服务？**
浏览器扩展做不了语音识别。Edge 内置的 `SpeechRecognition` 只吃麦克风输入，拿不到标签页的音频流。
所以必须把音频送到一个能跑 Whisper 的地方——放在本机是最便宜、也最保护隐私的选择。

**为什么字幕要永远在「顶层」？**
字幕层用 `popover="manual"` 放进了浏览器的 top layer。直接 append 到 `<body>` 的话，视频一全屏字幕就看不见了
（全屏元素会盖住普通内容）。另外全屏切换时会重新入栈，保证始终在最上面。默认 `pointer-events: none`，
所以字幕绝不会挡住你点视频、拖进度条。

**为什么字幕能像原生的那样贴住视频？**
见上面「字幕怎么『贴』到视频上」。核心是两件事：挑对 `<video>`，以及**算准画面矩形而不是元素矩形**。
`<video>` 的框和画面经常不是一回事 —— 900×600 的框里放 1280×720 的视频，上下各有 47px 黑边，
字幕要是贴在元素底边就会掉进黑边里。扩展会把这块刨掉再定位。

**为什么中间字幕会「变」？**
说话时服务会对「这句话到目前为止」的音频反复解码，所以文字会自我修正，跟 YouTube 自动字幕的观感一样。
检测到足够静音后才锁定成最终字幕。

**识别不是要等整句说完吗？**
不是。音频边收边识别，说完之后约 0.4 秒（静音判定）+ 一次解码出最终结果。
实测（N 卡 + DeepSeek，`sample_en.wav` / 带背景音乐版）：

| 场景 | 原文延迟 | **首见中文** | 最终译文 |
|---|---|---|---|
| 干净音频 | 0.60 s | **0.66 s** | 1.30 s |
| 语音 + 持续背景音乐 | 0.31 s | **0.40 s** | 0.98 s |

**「首见中文」才是用户真正感知的等待** —— 中文几乎紧跟原文出现，随后被更准的版本替换。

**怎么做到「又快又准」的？**
免费的机器翻译接口和 LLM 各有长处：免费接口 **100ms** 就出结果但缺上下文，
DeepSeek 翻译质量高但要 **600ms**（实测首字 625ms / 整句 704ms ——
瓶颈是模型「开始回话」的时间，不是写完整句，所以**流式几乎省不下来**）。

于是最终字幕会**同时发两条路**：

```
免费接口（~100ms）→ 先显示一版中文，用户几乎不用等
DeepSeek（~600ms）→ 准稿到了再替换，代词指代更准
```

中间字幕只走免费接口 —— 它本来就是给「正在说话时」看的，会被最终结果顶掉，
花 600ms 调 DeepSeek 既浪费钱又占住请求锁，反而拖慢最终字幕。

**踩过的坑：** 中间字幕的翻译跑得慢，可能在**定稿之后**才回来，
把已经显示好的准稿盖成半截话（实测出现过「二」「第一个是」这种被截断的译文）。
现在定稿时会取消上一句的翻译任务，并且发送前再查一次「这句是否已定稿」，过期的直接丢掉。

**识别模型默认用哪个？**
默认是 `auto`：**有显卡就用 `large-v3-turbo`，没显卡就用 `small`**。

为什么不是一个写死的模型 —— 因为显卡上「等静音」固定要 400 毫秒，而模型解码只要：

| 模型 | 显存 | 3.5s 短句 | 6.5s 长句 | 总延迟影响 |
|---|---|---|---|---|
| tiny | 0.4 GB | 36 ms | 48 ms | 不变 |
| base | 0.5 GB | 48 ms | 73 ms | 不变 |
| small | 0.7 GB | 117 ms | 178 ms | 不变 |
| medium | 1.2 GB | 268 ms | 382 ms | 不变（已贴近 400ms 边界） |
| **large-v3-turbo** | 1.2 GB | **311 ms** | **335 ms** | **不变** |

也就是说：**只要解码不超过 400 毫秒，换更大的模型总延迟完全不变，等于准确率白拿。**
`large-v3-turbo` 比 `medium` 又快又强，是这张表里最划算的一个。

但没有显卡时 `large-v3-turbo` 一次要好几秒，直接没法用 —— 所以必须按设备分开选，
这就是 `auto` 存在的原因。想强制指定就在弹窗里选具体模型。

**延迟是怎么一步步从 5.7 秒压到 0.6 秒的？**
前 5.7→1.5 秒是四个真实 bug，都是量出来的、不是猜的：

1. **收音频和解码挤在同一个线程里**。Whisper 解一次码要一秒多，这期间完全停止收音频，
   延迟一次次累加 —— 21 秒的音频能攒出将近 6 秒的滞后。改成两条线程（收音频 / 解码）后，
   音频位置始终咬住实时（实测滞后为 -0.17s，也就是音频比处理还快一点）。
2. **解码器被中间字幕占满**。一句话里既做中间解码、又做最终解码，总耗时超过这句话本身，
   解码器一旦饱和，最终字幕就永远排在后面。现在按**实测解码耗时**算「解码预算」，
   短句一次中间解码都不做（真实字幕本来就是一整行出现的），长句才做。
3. **「预终稿」复用**。一进入静音就抢先解一次，它的音频覆盖已经越过说话结束点，
   静音一确认就直接升格成最终字幕 —— 把「解码」和「等静音确认」重叠起来。
   升格前有**覆盖度检查**，确保绝不会把句子尾巴切掉。
4. **有背景音乐时句子永远不结束**。能量 VAD 检测不到静音（BGM 的能量一直在阈值之上），
   实测 21 秒音频只出 1 条字幕。现在加了「软切段」：超过 6.5 秒还没等到静音就主动切一刀。

剩下的 1.5→0.6 秒靠显卡：一次解码从 1170ms 降到 128ms。

**翻译为什么用 DeepSeek 而不是免费的？**
因为**免费机器翻译接口没法接收上下文**。同一句话：

```
前文：My brother bought a new car last week. / He said it was a gift for his wife.
原文：She really loves it.
免费接口 → 她真的很喜欢它。        ← "it" 指什么不知道
DeepSeek → 她真的很喜欢这辆车。    ← 正确解析
```

代价是钱和一点点延迟，但都很小：一部两小时电影约 **0.2~0.4 元**（`deepseek-flash`），
翻译比免费接口多花约 0.2~0.5 秒。

**踩过的两个坑（都已在代码里处理）：**

- **DeepSeek 默认开着「思考模式」**，而且推理强度默认 high。翻译根本不需要思考，
  实测延迟 1.3s → 3.2s，思维链还按输出 token 计费。代码里已经显式关掉
  （`{"thinking": {"type": "disabled"}}`）。
- **0.35 秒的请求限流是给免费接口设计的**，付费接口照搬只是白白加延迟 ——
  实测翻译额外耗时 1.53s → 0.52s。现在付费接口不限速。

**「一顿一顿」是怎么解决的？**
Whisper 一次解码的耗时是固定的（编码器永远跑满 30 秒窗口），所以中间字幕的更新频率
受解码速度限制。现在如果新文本是旧文本的延长（中间结果基本都在增长），
就只把新增的字用约 200ms 平滑显现，观感上像在连续打字；
文本被改写时直接替换，不会出现「先删后加」的鬼畜效果。
（尊重系统的「减少动效」设置，开了就改成瞬间替换。）

**字幕会不会「不同步」？上一个人的字幕还挂在下一个人说话的时候？**

**先说做不到的部分：真正的零延迟做不到。**
原生字幕零延迟是因为字幕文件**预先做好了、带精确时间轴**，播放器只是照着时间点显示。
而实时识别必须**先听到**才能转写 —— 这是本质差别，不是优化能消除的。
我们这套「等静音确认再解码」的方案，下限大约就是 0.3~0.5 秒。

**再说能做到的部分：「上一个人的字幕挂在下一个人说话时」不属于延迟问题，
属于显示策略问题，已经修掉了。**

识别有半秒到一秒延迟，等新字幕出来时说话的人往往已经换了，
旧字幕还挂在画面上就会被误当成下一个人的话。原生字幕不会这样，
是因为新 cue 一到旧 cue 立刻消失。我们没有时间轴，但
**「VAD 刚判断出有人开始说新一句」这个时刻是立刻就知道的** ——
服务端把这个信号（不带文字，只有几字节）马上发给客户端，
客户端立刻把旧字幕淡出并清掉。实测：信号后 60ms 透明度降到 0.38，460ms 后完全清除。

这样一来观感就同步了：**换人说话 → 旧字幕消失 → 新字幕随着说话长出来**。

**说话声音小就识别不到怎么办？**
根因是能量 VAD 的阈值。已经做了两件事：
- 阈值改成「跟着噪声底走」（滑动窗口 p15 分位），安静环境下阈值会自动降到很低
- `_has_speech` 兜底检查故意放宽，宁可多解一次也不漏

另外实测发现：**「整体音量小」其实不影响识别**（信噪比没变，Whisper 照样认得），
真正难的是**人声小但背景音正常**（信噪比被压掉）。这种情况靠软切段兜底，
不会出现「一句话都切不出来」。想要更好可以换更大的识别模型（`large-v3-turbo`）。

### 翻译服务

「自动」会**同时**向所有免费接口发请求，谁先返回用谁，并记住它（后续每条字幕只要几十毫秒）。
某个接口被限流或被墙会自动跳过并冷却一段时间。

| 服务 | 需要 Key | 国内直连 | 说明 |
| --- | :-: | :-: | --- |
| 微软 Edge 翻译 | 否 | 一般可以 | 免费，质量好 |
| Google 翻译 | 否 | ❌ | 国内不通，会自动跳过 |
| 有道翻译 | 否 | ✅ | 国内很快，中英质量不错（高频调用会被限流 411，会自动切走） |
| 腾讯翻译 | 否 | ✅ | 无需 Key，国内直连快，作为有道的备份 |
| MyMemory | 否 | ✅ | 有每日额度，被限流时会跳过 |
| DeepL | 是 | ✅ | 质量最好，需要付费 Key |
| OpenAI 兼容 | 是 | ✅ | DeepSeek / 通义 / 硅基流动 / 本地 Ollama 都行 |
| 不翻译 | — | — | 只显示识别原文 |

想用 DeepSeek 当翻译引擎，在设置页填：

```
OpenAI 地址：https://api.deepseek.com/v1
OpenAI 模型：deepseek-flash
OpenAI Key ：sk-xxxxxxxx
```

用本地 Ollama 就填 `http://127.0.0.1:11434/v1`，Key 留空。

**不填 Key 也能用**：会自动退回上面的免费接口竞速链，只是翻译质量差一些、
也没法利用上下文（代词和指代会翻不准）。

### API Key 放在哪（重要）

**仓库里不含任何 Key**，`server/config.json` 已在 `.gitignore` 里。
你有两种填法：

**方式一：设置页填**（最简单，走 `chrome.storage.sync`）
扩展设置页 → 翻译服务选 `openai` → 填 Key。缺点是会同步到浏览器账号云端。

**方式二：服务端本地文件**（推荐，不联网同步）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\set-api-key.ps1
```

它会让你粘贴 Key（**输入时不回显**，也不会留在命令历史里），然后写进 `server/config.json`。
想只看当前配置（打码显示）加 `-Show`：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\set-api-key.ps1 -Show
```

也可以手动复制模板再填：

```powershell
copy server\config.example.json server\config.json
notepad server\config.json
```

要换 Key 时，去 [DeepSeek 控制台](https://platform.deepseek.com/api_keys)
删掉旧的、建一个新的，再跑一遍上面的脚本即可。

也可以完全不落文件，用环境变量：

```powershell
$env:VST_OPENAI_API_KEY = "sk-xxxxxxxx"
powershell -ExecutionPolicy Bypass -File scripts\start-server.ps1
```

优先级：**内置默认值 < `server/config.json` < 环境变量 `VST_*`**。

> ⚠️ **`server/config.json` 千万别提交、别分享。** 它已经在 `.gitignore` 里了，
> 但如果你把整个文件夹打包发人，记得先把 Key 删掉。

**DeepSeek 默认开着「思考模式」**（推理强度还是 high），翻译根本用不上，
实测延迟会从 0.6 秒涨到 3 秒，思维链还按输出 token 计费。
本项目已经在请求里显式关掉它（`{"thinking": {"type": "disabled"}}`），你不用管。

## 常见问题

**Q：提示「连不上本地服务」**
确认 `start-server.bat` 窗口还在、没报错；浏览器打开 <http://127.0.0.1:8765/> 应该能看到状态页。
如果改了端口，扩展设置里的服务地址也要改。

**Q：一直停在「正在加载识别模型」**
第一次用某个模型要下载（`small` 约 250MB）。国内直连 HuggingFace 不通，服务会自动切到
`hf-mirror.com` 镜像。也可以手动指定后重启服务：

```powershell
$env:HF_ENDPOINT = "https://hf-mirror.com"
```

**Q：字幕卡顿 / 电脑很热**
换小模型：`scripts\start-server.bat --model base`。或者装好 CUDA 12 的 cuBLAS + cuDNN 9，
服务会**自动**改用显卡（有 N 卡会检测到，缺库会自动回退 CPU，不会报错）。

**Q：开始字幕后视频没声音了**
正常不会——捕获到的音频会接回扬声器。如果真遇到，先停掉字幕再开一次。

**Q：全屏看不见字幕**
默认用的是浏览器顶层机制，绝大多数网站全屏也能显示。个别网站不行的话，试试「影院模式」而不是全屏。

**Q：`edge://` 页面点开启报错**
浏览器内置页面（设置页、扩展商店、新标签页）不允许捕获音频，这是浏览器限制。切到普通网页再用。

**Q：翻译不出来**
设置页点「测试翻译」，会逐个列出哪个接口能用。免费接口被限流是常态，等一会儿或换服务。
长期用建议填个 Key。

**Q：模型和缓存占多少空间？**
模型存在 `server\models\`，各个模型合计几十 MB 到 1.5GB 不等，删掉这个文件夹就清空了（下次会重新下载）。

### WebSocket 协议

客户端 → 服务端：

| 消息 | 说明 |
| --- | --- |
| 二进制帧 | 16kHz 单声道 PCM（Int16 小端），建议每 64ms 一包（1024 采样点） |
| `{"type":"config", model, language, target_lang, translate, translate_partials, translator, ...}` | 会话配置 |
| `{"type":"flush"}` | 立刻结束当前这句 |
| `{"type":"ping"}` | 心跳 |

服务端 → 客户端：

| 消息 | 说明 |
| --- | --- |
| `{"type":"hello", version, model, sample_rate}` | 连接建立 |
| `{"type":"status", state, message}` | `loading` / `ready` / `config`…… |
| `{"type":"line", id, final, source, translated, lang, t0, t1}` | 一条字幕。中间字幕反复更新；`final:true` 表示定稿 |
| `{"type":"stats", rtf, language}` | 性能统计（每 5 秒） |
| `{"type":"error", message}` | 出错 |

同一条字幕的原文和译文可能分两条消息到达（翻译是异步的），客户端按 `id` 合并即可。

## 已知限制

- **必须有本地服务**。这是浏览器扩展能力的硬边界，不是偷懒。
- 部分使用特殊加密播放器的网站（某些 DRM 视频）音频不走标准通道，抓不到。
- 免费翻译接口会被限流，长期重度使用建议配 Key。
- 纯 CPU 跑 `medium` / `large-v3` 会跟不上实时，页面上会显示实时率供你判断。
- 纯音乐、多人同时说话、强背景音乐的场景，识别准确率会明显下降（所有 Whisper 方案的共同问题）。
- 只在 Edge / Chrome 等 Chromium 浏览器上验证过（Firefox 的 MV3 实现不同，不适用）。

## 隐私

- **视频音频不出你的电脑。** 识别全程在本机跑，音频只经 `ws://127.0.0.1` 送到本地服务。
- **只有文字会发出去**：识别出的原文会发给翻译服务（免费接口，或你自己配的 DeepSeek / DeepL）。
  不想发就设置页选「不翻译」，那就纯本地。
- 扩展不收集、不上报任何数据。
